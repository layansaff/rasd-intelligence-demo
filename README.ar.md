# RASD Intelligence

نموذج محلي لتقييم مخاطر تعطل المورّد واستمرارية الأعمال. يتضمن واجهة ويب متجاوبة، وواجهة API مبنية بـFastAPI مع تحقق صارم، وسجل تقييمات دائمًا في SQLite.

> **تنبيه للاستخدام في القرارات:** الدرجة تقدير أولي حتمي قائم على قواعد محددة، ولم تتم معايرتها أو التحقق منها على بيانات خسائر تشغيلية. لا تستخدمها وحدها لاتخاذ قرارات اعتماد مورّد أو تأمين أو تمويل أو أي قرار مؤثر. يجب أن يراجع مختص النتيجة وافتراضاتها.

## التشغيل المحلي

يتطلب Python 3.10 أو أحدث:

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements-dev.txt
Copy-Item .env.example .env
python -m uvicorn backend.main:app --env-file .env --host 127.0.0.1 --port 8000
```

افتح <http://127.0.0.1:8000/ui>. توثيق API التفاعلي في <http://127.0.0.1:8000/docs> وفحص الصحة في <http://127.0.0.1:8000/health>.

يحفظ التطبيق السجل افتراضيًا في `data/rasd.sqlite3`. احتفظ بالملف في مكان خاص وأدرجه في النسخ الاحتياطية. لتغيير المسار استخدم المتغير `RASD_DATABASE_PATH`.

إذا استضفت الواجهة على عنوان منفصل، اضبط `RASD_CORS_ORIGINS` على قائمة مفصولة بفواصل من عناوين المصدر الموثوقة بالكامل، مع البروتوكول والمنفذ. الإعداد الافتراضي يسمح بمصدري التطوير المحليين المعتادين على المنفذ 5500 فقط.

## الاختبارات

```powershell
python -m pytest -q
```

تستخدم الاختبارات قواعد بيانات مؤقتة ولا تعدّل ملف بيانات التطبيق الافتراضي.

## واجهات API

- `GET /health`: حالة الخدمة وقاعدة البيانات.
- `POST /analyze-risk`: التحقق من المدخلات والحساب وحفظ النتيجة.
- `GET /assessments?limit=50&offset=0`: صفحات سجل التقييمات.
- `GET /assessments/summary`: إحصاءات دقيقة لكل التقييمات المحفوظة.
- `DELETE /assessments`: مسح السجل المحفوظ نهائيًا.
- `GET /docs`: توثيق OpenAPI التفاعلي.

## Docker Compose

```powershell
docker compose up --build
```

يربط Compose الخدمة على `127.0.0.1:8000` ويحفظ قاعدة البيانات في وحدة تخزين دائمة. تعمل الحاوية بمستخدم غير root وتتضمن فحص صحة. خذ نسخة احتياطية من وحدة التخزين قبل نقل النشر أو استبداله.

## عرض عام للمحفظة على Render

يعرّف `render.yaml` خدمة ويب تجريبية مجانية في فرانكفورت. هذه النسخة تشغّل `RASD_DEMO_MODE=true`: تحسب النتيجة، لكنها لا تنشئ قاعدة بيانات ولا تحفظ تقييمات الزوار على الخادم، وتخفي توثيق API. تظهر نتيجة كل زائر وسجله مؤقتًا في المتصفح الحالي فقط. استخدم بيانات وهمية، ولا تدخل أسماء أشخاص أو بيانات مورّدين حقيقية.

1. ارفع ملفات المشروع إلى مستودع GitHub، ولا ترفع `.env` أو مجلد `data` أو ملفات قواعد البيانات.
2. في Render أنشئ **Blueprint** واربطه بالمستودع؛ سيقرأ إعداد الخدمة من `render.yaml`.
3. بعد اكتمال النشر افتح عنوان `onrender.com` ثم أضف `/ui`، واختبر التقييم من نافذة خاصة.
4. أضف رابط العرض إلى ملفك في LinkedIn بعد التأكد أن `/health` يعرض `demo_mode: true` و`storage: disabled`، وأن `/docs` غير متاح.

الخطة المجانية توقف الخدمة بعد 15 دقيقة دون زيارات، وقد يستغرق أول طلب بعد الخمول نحو دقيقة حتى تعود. الملفات المحلية مؤقتة وتُحذف عند إعادة التشغيل؛ لذلك هذا الإعداد لعرض المحفظة فقط، وليس لحفظ بيانات أو لاستخدام تشغيلي.

## منهجية التقييم وحدودها

تعرض النتيجة درجة المخاطر المتبقية والدرجة الكامنة وعوامل التقييم والتوصيات. أوزان الدرجة المتبقية هي: الأثر 35%، احتمال التعطل 25%، التعافي 20%، الاعتماد بعد التخفيف 10%، والضوابط 10%. تخفّض الجهة البديلة الاعتماد 25 نقطة بحد أدنى صفر. التصنيف: منخفض 0–39، متوسط 40–69، مرتفع 70–100. تفاصيل القيم وحدود التعافي في `README.md`.

هذه القيم للعرض التوضيحي وليست احتمالات معايرة. يجب اعتماد الأوزان والحدود والتوصيات من الجهة المستخدمة قبل أي استخدام تشغيلي، ولا يتضمن المشروع معايرة إحصائية أو اختبارًا تاريخيًا أو مراجعة تحيز أو تحققًا مستقلًا للنموذج.

## جاهزية الإنتاج

الوضع الافتراضي للتطبيق محلي، ويستخدم SQLite دون تشفير، ولا يتضمن تسجيل دخول أو صلاحيات أو عزل مستأجرين أو سجل تدقيق مقاومًا للتعديل. لا تعرّض وضع الحفظ الافتراضي للإنترنت. وضع العرض العام أعلاه لا يحفظ بيانات الزوار، لكنه يظل نموذجًا توضيحيًا لا خدمة إنتاج. يتطلب الاستخدام التشغيلي هوية وصلاحيات معتمدة، وتشفيرًا أثناء النقل والتخزين، وإدارة أسرار، ونسخًا احتياطيًا واختبار استعادة، ومراقبة، وضوابط احتفاظ، ومراجعة أمنية وحوكمة للنموذج.
